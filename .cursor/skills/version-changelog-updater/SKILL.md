## Ποιος κάνει τι

- **Η ΤΝ (εσύ):** προσθέτει εγγραφές **ΜΟΝΟ** στην ενότητα `"version": "Unreleased"` (πρώτο στοιχείο της λίστας) του `assets/changelog.json`.
- **Η εφαρμογή («Δημοσίευση έκδοσης», οθόνη Σεναρίων — debug):** σφραγίζει το Unreleased σε αριθμημένη έκδοση, ορίζει την ημερομηνία, κάνει bump το `pubspec.yaml` (minor αν υπάρχει `added`, αλλιώς patch), χτίζει και διανέμει. **ΜΗΝ κάνεις χειροκίνητα bump έκδοσης, ΜΗΝ σφραγίζεις εκδόσεις, ΜΗΝ ορίζεις ημερομηνίες** — είναι δουλειά της Δημοσίευσης.

## Μορφή του changelog.json

Λίστα αντικειμένων, νεότερα πρώτα· το πρώτο είναι πάντα το Unreleased:

```json
{
  "version": "Unreleased",
  "date": "",
  "added": ["…"],
  "improvements": ["…"],
  "changed": ["…"],
  "fixed": ["…"]
}
```

Κανόνες:

- Έγκυρο JSON (UTF-8) — μετά από κάθε επεξεργασία επιβεβαίωσε ότι κάνει parse.
- Κατηγορίες: `added` (νέα λειτουργία), `improvements` (μικροβελτιώσεις), `changed` (αλλαγή συμπεριφοράς), `fixed` (διορθώσεις). Κενή κατηγορία → `[]`.
- `version` χωρίς build suffix. `date` κενό στο Unreleased — το γεμίζει η Δημοσίευση.
- Μην πειράζεις σφραγισμένες (αριθμημένες) εγγραφές, εκτός αν ο χρήστης ζητά ρητά διόρθωση κειμένου.

## Τι καταγράφεται / τι αγνοείται

Μόνο **ουσιαστικές** αλλαγές, σε **άπταιστα ελληνικά**, με οπτική του χρήστη (τι βλέπει/κερδίζει, όχι τεχνική ορολογία):

- Νέο feature → `added`
- Μικροβελτίωση εμπειρίας → `improvements`
- Ορατή αλλαγή συμπεριφοράς → `changed`
- Διόρθωση σφάλματος → `fixed`

**Αγνόησε:** refactor χωρίς ορατή αλλαγή, τεστ, τεκμηρίωση, ορθογραφία σε σχόλια, μετονομασίες.

## Πού εμφανίζεται η έκδοση στην οθόνη (αυτόματα από `pubspec`)

| UI | Αρχείο | Πώς παίρνει την έκδοση |
|----|--------|-------------------------|
| Chip έκδοσης | `version_chip.dart` | `appVersionProvider` → `versionChipLabel()` |
| Τίτλος παραθύρου | `main.dart` | `windowTitleWithVersionLabel()` |
| Διάλογος ιστορικού | `changelog_dialog.dart` | `appVersionProvider` + `entry.date` |

Μην hardcode έκδοση σε widgets. Ο τίτλος παραθύρου αλλάζει με πλήρη επανεκκίνηση (όχι hot reload).

## Κλήση (invocation)

Όταν ο χρήστης γράφει `/changelog`, `/ιστορικό-εκδόσεων`, ή ζητά ενημέρωση changelog / release notes, εφάρμοσε αυτό το skill: πρόσθεσε τις εγγραφές στο Unreleased του `assets/changelog.json` και τίποτα άλλο. Αν ζητηθεί bump έκδοσης, εξήγησε ότι γίνεται από την ενσωματωμένη «Δημοσίευση έκδοσης» της εφαρμογής.
